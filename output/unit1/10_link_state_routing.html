Link State Routing

A routing method in which each router builds a map of network topology and computes shortest paths using that map.

Routing algorithmTopology databaseDijkstra's algorithmExam-ready notes

1. Core idea

In link-state routing, routers learn the state and cost of their directly connected links. They distribute this information so routers can construct a view of the network. Each router then independently calculates the best paths to destinations.

Remember: Link-state routing distributes information about links; each router uses the collected topology to calculate routes.

A link's cost may represent distance, delay, bandwidth-related cost, or another configured metric. The exact metric depends on the network and protocol.

2. Link-state routing workflow

Keep these steps in order for an exam answer.

  1. Discover neighbours: determine which routers are directly connected.
  2. Determine link costs: measure or configure the cost of each direct link.
  3. Create a link-state packet (LSP): include router identity, neighbours, link costs, and freshness information such as sequence number and age.
  4. Distribute the LSP: flood it through the routing domain so routers can collect link-state information.
  5. Build the topology database: combine received information into a graph of routers and links.
  6. Compute shortest paths: run Dijkstra's algorithm with the local router as the source.
  7. Install routes: use the paths to determine next hops and populate the routing/forwarding table.

Sequence numbers help distinguish newer information from old copies. An age/lifetime field allows stale information to expire. Exact packet fields and procedures vary by protocol.

4. Dijkstra's algorithm

Dijkstra's algorithm finds shortest paths from one source in a graph with non-negative link costs.

  1. Set the source distance to 0 and all other distances to infinity.
  2. Choose the unvisited router with the smallest tentative distance.
  3. Mark that router as finalized.
  4. For each neighbour, test whether going through the selected router gives a lower cost.
  5. If lower, update the neighbour's distance and predecessor.
  6. Repeat until all reachable routers are finalized.
  7. Trace predecessor links to recover each path and determine the first hop.
D(v) ← min(D(v), D(u) + c(u,v))

D(v) is the current best-known distance to router v; c(u,v) is the link cost between u and v.

Do not confuse: Dijkstra's algorithm is the path-computation algorithm. Link-state routing is the overall method that collects and distributes topology information.

5. Link-state packet distribution

Routers distribute link-state packets using controlled flooding. A router forwards a newly accepted LSP to its neighbours, subject to the protocol's rules.

  • Sequence number: helps identify newer information from the originating router.
  • Age or lifetime: prevents old information from remaining indefinitely.
  • Duplicate suppression: avoids repeatedly processing and forwarding the same LSP.
  • Reliable distribution: practical protocols include mechanisms to handle loss and synchronize databases.

These are general design concepts. Exact fields, acknowledgements, timers, and flooding rules depend on the routing protocol.

7. Advantages

  • Routers compute routes using a detailed topology view.
  • Shortest paths can be calculated using link costs.
  • Topology changes can be distributed and routes recalculated.
  • Sequence numbers, aging, and duplicate handling help manage stale information.
  • Can support larger routing domains when combined with hierarchy and suitable protocol design.

8. Limitations and challenges

  • Topology database storage consumes memory.
  • Shortest-path computation consumes CPU, especially after changes.
  • Flooding creates control traffic.
  • Routers may temporarily have inconsistent databases while updates propagate.
  • Incorrect costs or stale information can lead to undesirable routes.

3 marks: Define link-state routing.

Link-state routing is a method in which each router discovers its directly connected neighbours and link costs, distributes this information through the routing domain, builds a topology database, and independently computes shortest paths—commonly using Dijkstra's algorithm—to create its routing table.
