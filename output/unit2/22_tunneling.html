22. Tunneling

Visual study notes on carrying packets through an intermediate network using encapsulation, with a step-by-step diagram, example, comparisons, and exam practice.

Study-source note: These notes explain the standard networking concept of tunneling. Check your prescribed Unit 2 PPT for its exact examples and depth; examples here are illustrative.

1. Learning objectives

  • Define tunneling and explain why it is used.
  • Describe encapsulation and decapsulation.
  • Explain the tunnel endpoints and packet journey.
  • Distinguish tunneling from ordinary forwarding and encryption.
  • State benefits, limitations, and common use cases.

2. What is tunneling?

Tunneling is a technique in which a packet of one protocol is encapsulated inside another packet so it can cross a network that may not directly support or route the original packet type. The outer packet is forwarded through the intermediate network; at the tunnel endpoint, the outer header is removed and the original packet is recovered.

Core idea: original packet → encapsulate inside an outer packet → transport across the tunnel → decapsulate at the far endpoint.

The intermediate network mainly forwards using the outer header. The inner packet remains carried as payload until it reaches the tunnel endpoint.

4. Why is tunneling needed?

  • Protocol compatibility: carry a packet across a network that does not natively route the inner protocol.
  • Virtual private networks: connect remote sites or users across a shared network.
  • Overlay networks: build a logical network over an existing physical network.
  • Traffic engineering and transitions: support selected network architectures or migration arrangements.
Important: tunneling does not automatically provide confidentiality or authentication. Those protections require suitable security mechanisms, often including encryption and integrity protection.

5. Encapsulation — what does a packet look like?

Outer header
used to route across the intermediate network
Inner/original packet
original header + original payload

The outer header is added around the complete inner packet. The inner packet is not replaced; it is carried as payload.

Encapsulation increases packet size because an additional header (and possibly other fields) is added. This overhead must be considered when selecting a tunnel design and MTU.

6. Worked example: connecting two private networks

Suppose two company offices use a private network addressing scheme, but the offices are connected through a provider network that routes only the provider's outer IP packets.

  1. A host at Office A sends an inner packet toward a host at Office B.
  2. The tunnel ingress encapsulates that packet in an outer IP packet addressed to the tunnel endpoint at Office B.
  3. Provider routers forward the outer packet across the provider network.
  4. The remote tunnel endpoint removes the outer header.
  5. The recovered inner packet is forwarded into Office B toward the destination host.
Remember: the provider network transports the encapsulated packet; the tunnel endpoints handle the inner packet at the tunnel boundaries.

7. Tunneling vs. ordinary forwarding vs. encryption

ConceptMain operationDoes it automatically encrypt data?
Ordinary forwardingRouter examines the packet header and forwards the packet to the next hop.No.
TunnelingEncapsulates a packet inside another packet to carry it through an intermediate network.No.
EncryptionTransforms data so it cannot be read without the appropriate key.Encryption is the operation itself.

A VPN tunnel may combine tunneling with encryption, but the terms are not interchangeable. Some tunnels carry unencrypted packets.

8. Benefits and limitations

✅ Benefits

  • Connects networks across an incompatible or shared infrastructure.
  • Enables logical overlay networks.
  • Can support VPN connectivity when combined with suitable security.
  • Hides inner addressing from intermediate forwarding decisions in many designs.

⚠️ Limitations

  • Extra headers add overhead.
  • Encapsulation can cause MTU and fragmentation issues.
  • Tunnel endpoints add configuration and troubleshooting complexity.
  • Security is not guaranteed unless explicitly provided.

10. Practice questions

Q1. What is encapsulation?

Adding an outer protocol header around the original packet so it can be carried through the tunnel.

Q2. What does the tunnel egress do?

Decapsulates the packet by removing the outer header and recovering the inner packet.

Q3. Do intermediate routers normally need to interpret the inner packet to forward the tunnel packet?

No; they generally forward using the outer header.

Q4. Does tunneling always encrypt traffic?

No. Encryption must be provided by a suitable security protocol or mechanism.

Q5. Name one drawback of tunneling.

Additional header overhead, possible MTU/fragmentation issues, or added configuration complexity.

Q6. Give one use of tunneling.

Connecting remote private networks over a shared provider network.

11. Quick revision

  • Tunneling: carry an inner packet inside an outer packet.
  • Ingress endpoint: encapsulates.
  • Intermediate routers: forward using the outer header.
  • Egress endpoint: decapsulates.
  • Common uses: VPNs and overlay networks.
  • Main benefit: carry packets across an intermediate network.
  • Main costs: extra header overhead and possible MTU issues.
  • Security reminder: tunneling alone does not mean encryption.

📘 Exact example and analogy from the PPT

The lecture example connects an IPv6 network in Paris to another IPv6 network in London through an intermediate IPv4 Internet. Tunneling allows the original packet to cross the unlike intermediate network; multiprotocol routers connect the networks.

PPT analogy: a car drives through France, is carried as freight by a high-speed train through the Channel tunnel, then continues driving on English roads. The car is the original packet; the train journey represents carriage through the intermediate network.
