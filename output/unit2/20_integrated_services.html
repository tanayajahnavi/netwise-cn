20. Integrated Services (IntServ)

Visual study notes on the Integrated Services approach to Quality of Service (QoS), with diagrams, a reservation walkthrough, exam answers, and revision questions.

Study-source note: These notes explain the standard networking concept of IntServ. Check the wording and depth against your prescribed Unit 2 PPT; details not confirmed from the PPT are not presented as quotations from it.

1. Learning objectives

  • Define Integrated Services (IntServ).
  • Explain why resource reservation may be needed for applications with QoS requirements.
  • Describe the general reservation flow and the role of RSVP.
  • Distinguish IntServ from best-effort delivery and DiffServ.
  • State benefits, limitations, and exam-ready points.

2. What is Integrated Services?

Integrated Services (IntServ) is a QoS architecture in which an application can request specific network service characteristics for a flow. The network attempts to reserve the resources required to provide the requested service, subject to admission checks.

A flow is a stream of packets associated with a communication session or application. IntServ is commonly described with per-flow resource management: routers along the path maintain information for flows that receive reserved service.

Core idea: request resources for a flow → check whether the network can support the request → admit and reserve resources if possible.

IntServ does not mean that every request must be accepted. A request may be rejected if the network cannot meet the requested service level.

3. Why use IntServ?

🎙️ Real-time voice

Needs low delay and low variation in packet arrival time to keep conversation natural.

📹 Interactive video

Benefits from predictable delivery and sufficient bandwidth.

📁 Ordinary data transfer

May tolerate variable delay, depending on the application, and often uses best-effort service.

On a best-effort network, packets are forwarded without a per-flow guarantee that a particular bandwidth or delay target will be met. IntServ provides a framework for requesting more predictable treatment.

Conceptual view: the request and resource-management mechanisms coordinate the routers along the path.

  • Flow specification: describes the traffic and service requested.
  • Admission control: decides whether enough resources are available to accept the request.
  • Resource reservation: allocates or accounts for resources such as bandwidth and buffering.
  • Packet classification and scheduling: identify packets belonging to a flow and provide the requested treatment.

5. How an IntServ reservation works

  1. Application defines its need. It specifies traffic characteristics and the desired QoS.
  2. Reservation signalling begins. A signalling protocol communicates the reservation request along the route.
  3. Routers examine the request. Each relevant router performs admission control and checks local resource availability.
  4. Resources are reserved if accepted. Routers establish the state and packet-handling treatment needed for the flow.
  5. Data packets are sent. Routers identify the flow and apply the appropriate scheduling or policing behaviour.
  6. Reservation state is maintained or removed. Signalling and state-management mechanisms keep the reservation current and release resources when no longer needed.

Important: a reservation is not a promise that every packet will arrive under all possible failures. It is a network QoS mechanism operating under its defined assumptions and conditions.

6. RSVP and IntServ

RSVP (Resource Reservation Protocol) is commonly associated with signalling reservations in IntServ networks. It carries reservation-related information so that routers on a path can establish and maintain resource state.

  • RSVP is a signalling protocol; it is not itself the scheduler or the physical resource.
  • Routers still need mechanisms for admission control, packet classification, and resource handling.
  • RSVP is commonly described as receiver-oriented: receivers participate in requesting the resources needed for a data flow.
Exam phrasing: “IntServ provides the QoS service architecture; RSVP can be used to signal resource reservations.”

Memory cue: IntServ = individual flow reservation; DiffServ = differentiated treatment of traffic classes.

9. Advantages and limitations

✅ Advantages

  • Supports explicit resource requests for flows.
  • Admission control can prevent accepting more reserved traffic than available resources support.
  • Can provide more predictable QoS for suitable real-time applications.
  • Allows different service requirements for different flows.

⚠️ Limitations

  • Per-flow state increases router processing and memory needs.
  • Reservation signalling and maintenance add complexity.
  • Large numbers of flows can make deployment and scaling difficult.
  • QoS depends on correct traffic descriptions, admission decisions, and router support.

10. Worked conceptual example

Suppose a voice flow requests a reservation of 1 Mb/s on a path whose bottleneck link has 10 Mb/s capacity. Existing accepted reservations use 8.5 Mb/s, and the admission policy allows only the available residual capacity to be reserved.

StepCalculation / decision
Capacity10 Mb/s
Already reserved8.5 Mb/s
Residual capacity10 − 8.5 = 1.5 Mb/s
New request1 Mb/s
DecisionIt may be admitted because 1 Mb/s ≤ 1.5 Mb/s, assuming no other constraint blocks it.

Illustrative arithmetic only; real admission decisions can include overhead, traffic descriptors, delay requirements, and policy limits.

11. Exam-ready answers

3 marks — Define IntServ.

Integrated Services (IntServ) is a QoS architecture that allows an application to request specific service characteristics for a flow. The network uses signalling and admission control to determine whether resources can be provided. If the request is accepted, routers maintain the state needed to support the requested treatment.

5 marks — Explain the working of IntServ.

  1. An application specifies its traffic and QoS requirements.
  2. Reservation signalling communicates the request along the path.
  3. Each router performs admission control.
  4. If resources are available, the router reserves or accounts for them and maintains flow state.
  5. Packets are classified and handled using the relevant scheduling and resource-management mechanisms. If a request cannot be supported, it is rejected.

8–10 marks — Explain Integrated Services with a neat diagram.

Begin with the definition and need for QoS. Draw the path Application → ingress router → intermediate routers → receiver. Explain the flow specification, RSVP signalling, admission control, resource reservation, packet classification and scheduling. Describe the reservation decision (accept or reject), then list advantages and limitations. End by comparing per-flow IntServ with class-based DiffServ.

12. Practice questions

Q1. What is the main purpose of IntServ?

Answer hint: to request and manage QoS resources for individual flows.

Q2. What is the role of admission control?

Answer hint: determine whether the network can support a new reservation without violating its resource constraints.

Q3. Expand RSVP.

Answer: Resource Reservation Protocol.

Q4. State one major limitation of IntServ.

Answer hint: per-flow state and signalling overhead can limit scalability.

Q5. Give two differences between IntServ and DiffServ.

Answer hint: per-flow vs. per-class treatment; per-flow reservation state vs. aggregated class handling.

Q6. Does IntServ accept every reservation request?

Answer: No. A request can be rejected if the network cannot meet its resource or policy requirements.

13. Quick revision sheet

  • IntServ: QoS architecture with per-flow resource management.
  • Flow: related packet stream associated with a communication session.
  • Admission control: accept or reject a reservation request.
  • RSVP: signalling protocol commonly used for resource reservation.
  • Guaranteed service: associated with a bound on queuing delay under stated conditions.
  • Controlled-load service: aims to approximate performance of a lightly loaded network.
  • Main strength: explicit per-flow QoS/resource control.
  • Main limitation: per-flow state and signalling overhead at scale.
  • IntServ vs DiffServ: per-flow reservation vs. aggregated traffic-class treatment.
Before the exam: practise drawing the architecture and reservation decision diagram, and keep the distinction between IntServ, RSVP, admission control, and DiffServ clear.

📘 Lecture focus: multicast RSVP reservations

The PPT focuses on streaming multimedia and both unicast and multicast. Dynamic multicast membership makes it difficult for a sender to reserve exactly the resources every receiver will need in advance.

  1. Multicast routing builds a spanning tree for the group; the group has a multicast address.
  2. A receiver sends a reservation message up the tree toward a sender, using the reverse-path-forwarding method described in the lecture.
  3. At each router, the request is recorded and the required bandwidth is reserved. WFQ may be used for scheduling.
  4. If sufficient bandwidth is unavailable, the request fails. When the reservation message reaches the sender, the path has been reserved for that receiver.
  5. A receiver watching two independent sources needs separate channels on the relevant segments. Where receivers share a path and sufficient bandwidth is already reserved, it need not be reserved twice.
  6. The PPT says differing receiver requests should be satisfied for the “greediest” receiver; explain this as the lecture’s shared-reservation rule rather than a universal statement about all QoS systems.

The PPT’s RSVP examples use multiple multicast senders and receivers, including hosts 1 and 2 as senders and hosts 3, 4 and 5 as receivers.
